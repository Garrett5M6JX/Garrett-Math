# Garrett Math — V28 a V30

## V28 — Configuración global
- Panel de ajustes para nombre, aviso general, etapa inicial sugerida y tiempo de inactividad administrativa.
- Persistencia en gm_platform_settings, con acceso restringido al superadministrador por RLS.
- Secretos y claves API permanecen fuera del navegador y se gestionan en Vercel.
- Las preferencias se consumen en las pantallas que se integren explícitamente con ellas; no se afirma que cambien toda la plataforma automáticamente.

## V29 — Preparación de automatizaciones
- Registro de reglas administrativas con eventos y acciones permitidas.
- Crear y eliminar reglas en estado borrador.
- RLS de superadministrador.
- Las reglas quedan forzadas a enabled=false por restricción SQL.
- No hay ejecución en segundo plano, scheduler, notificaciones ni worker en este lote. Esto requiere una fase posterior con backend seguro, control de frecuencia y bitácora de ejecuciones.

## V30 — Optimización
- Carga diferida (React.lazy + Suspense) de los módulos administrativos secundarios.
- Reduce el JavaScript inicial del panel; cada módulo se descarga cuando el administrador lo abre.
- Sin dependencias nuevas.

## Activación de base de datos
Revisar y ejecutar manualmente supabase/admin_v28_v29_v30.sql en Supabase SQL Editor después de confirmar la migración base admin_v11.sql y el sistema de superadministrador. La migración es aditiva y no se ejecuta desde el código.
